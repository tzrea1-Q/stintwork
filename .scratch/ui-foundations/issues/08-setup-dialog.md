# 08 — Setup dialog organised by check

Status: ready-for-agent
Blocked by: none

## What to build

The maintainer and coordinator's review on 2026-10-13 found Setup unacceptable:

- A multi-step file-writing and committing task lives in a 468px Popover. Outside clicks lose selections, and internal scrolling hides the next action.
- The detection checklist and fixed proposed-file list do not relate. Found checks still receive changes; missing local Markdown tracking has no visible fix; .gitignore and roadmap have no check; a missing glossary has neither fix nor explanation.
- The text-xs title is smaller than items. Green checks, radio-like empty circles and blue checkboxes compete; missing status is only announced to screen readers.
- Paths repeat in labels and preview headings; bracketed create/change text and bare details triangles add noise. Checks do not explain what is wrong or why it matters.
- Read-only Agent skill availability is stacked into the same task.

Replace Setup with a shared Dialog opened by the top-bar chip, retaining its ready/total count. Title: “Set up project” / “设置项目”. Include a one-line attention/file-count/one-commit summary. Organise one list by check, with visible success/warning status Badges, check name and one-line purpose. Attention rows show mapped file toggles, create/change Badges and shared expandable diff previews using CodeBlock. Show each path once; fold ready checks into one expandable count row. Make change-to-check or independent-reason mapping explicit in core's plan; keep the server API backward-compatible with tests. Independent changes explain local-run-data exclusion and milestone roadmap creation. Missing glossary/decision records explain why Setup does not author project-specific memory; do not invent a glossary template.

Keep Cancel and the primary “Review changes (N)” action in a persistent footer. Review shows only selected diffs and ends with “Confirm and commit”; success shows the commit and Close. Preserve refusal, error, loading, empty and retry states. Use the existing CreateWorkItem dismissal policy: guard pending writes, otherwise allow Escape/outside dismissal and return focus to the chip. Put Agent skill availability and its read-only explanation in a separate collapsed-by-default section. All new copy belongs in en/zh-CN catalogs and follows GLOSSARY terms.

Add “Choosing a container” to the frontend guide: Popover for glanceable information or a single immediate action; Dialog for multi-step tasks, forms, file writes or commits; Sheet for browsing a work item or queue beside the board; Tooltip only for labels. Audit other popovers and record/fix violations.

Scope: packages/web, setup mapping in packages/core/packages/server, docs/agents/frontend.md and tickets 07/08. No dependency changes or commits. New source files carry SPDX headers. Follow ADR 0010 and the frontend guide's Visual language and Done checklist.

## Acceptance criteria

- [x] Setup uses the shared Dialog, mapped check rows, status/action Badges, shared toggle and expandable previews; paths do not repeat and ready checks collapse together.
- [x] Every missing check has a visible fix or a reason for manual project-memory authoring; independent file changes explain their purpose.
- [x] Selection, preview, review, confirm, success, loading, empty, refusal and retry work; skills are initially collapsed and read-only; dismissal guards pending writes and returns focus to the chip.
- [x] Core/server tests prove mapping and compatibility with confirmations without mapping metadata.
- [x] Behaviour tests cover open, toggle, preview, review, confirm, refusal, retry, keyboard actions and focus return; new shared components have behaviour tests.
- [ ] Browser cases and screenshots cover 1440/1024/768/390/360px in en/zh-CN and the suite's colour schemes. Footer controls stay visible at 390/360px with long previews; no page overflow, accidental clipping or overlay gutter violations.
- [ ] Comments record the popover audit, actual checks and coordinator browser/screenshot review at 1440/390px in both languages before merging. Ticket 07 waits for 06 and 08; M8 remains active until its exit passes.
