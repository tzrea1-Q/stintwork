# Stintwork v0.1.1

Released on npm on 2026-10-12. Version 0.1.0 was published on npm on 2026-10-11.

## What changed

### Local data and risky files

`.stintwork/local/` now ignores itself. Stint logs, check logs and pull request check records stay out of the project's Git even without Project setup. Stintwork does not edit the project's `.gitignore` outside confirmed Project setup.

Checkpoints exclude likely secrets, files over 1 MiB and generated directories. The handoff, Review and Needs you show excluded paths without file contents. Commits made during a stint are also scanned. The Review gate blocks shipping risky files unless they are removed or individually accepted with a reason. Accept is tied to the file's blob; changing the file requires another decision. Detection is by path and size, not content.

### Starting stints and approving gates

Quick's Do and Bug's Diagnose can start from the intent without tickets. Do without tickets needs a finished stint before approval. Ticket-scoped Do stints still work.

Gate approvals commit `workflow.yaml`, including in the main checkout before a worktree exists. If the commit fails, the file is restored instead of leaving an uncommitted gate change.

Agents get one 60-second startup budget. A timeout explains that the machine may be busy. Codex availability is checked before a stint, with missing CLI and login guidance in the agent picker and Needs you. Use Refresh agent availability after installing or signing in.

### Documentation

Both READMEs explain where to run `npx stintwork` and how to set up the agents you choose. The package now includes the Simplified Chinese README.

The existing review and shipping behaviour is unchanged: real `gh` "no checks reported" output is handled, Review diffs support a `master` main branch, and merge-method selection honours readable linear-history protection. These fixes were already in v0.1.0.

## Upgrade

Stop the running Stintwork server. From your project's main checkout and main branch, run:

```bash
npx stintwork@latest
```

Or select this version explicitly:

```bash
npx stintwork@0.1.1
```

Node.js 22.12 or newer, Git and at least one installed, signed-in Claude Code or Codex CLI are still required. The package does not install or sign in to agent CLIs.

## Known limitations

The [v0.1.0 limitations](0.1.0.md#known-limitations) still apply:

- Grok Build is experimental and not verified end to end. There is no terminal fallback for agents without ACP.
- Tickets stay in local Markdown. Stintwork does not read or sync GitHub Issues; pull requests and CI use `gh` separately.
- Only one stint can be active per work item. Different work items can run stints at the same time.
- Permission levels depend on requests the agent sends. They are not an independent security boundary; Codex can run commands without asking.
- Real GitHub checks covered opening and closing a pull request and choosing a merge method. Actual `gh pr merge` and post-merge cleanup remain covered by fake-`gh` tests, not a completed real GitHub merge.
- Skill detection only checks for files in supported locations. Stintwork does not install skills or handle credentials.
- Server restarts interrupt active stints. Continue with a new stint from the recorded state.
- Rejecting a memory proposal restores the whole file to the stint's starting version, including later committed changes. Inspect the diff first.
- Workflows are ordered stages, not branches. Each workflow must end with a merge gate in Ship.

The M5 exit test with 3–5 developers outside the project remains deferred. Risky-file detection is not a content scan or a security boundary. Rotate real secrets if they have been committed.
