# Stintwork v0.2.0

**Draft:** Update these notes against the final release revision and record the ACP contract results before release.

## What changed

### Project setup and the interface

Project setup preserves an existing tracker guide by default. Switching another tracker to local Markdown is an explicit, initially unselected change; the review shows removed lines before confirmation. Existing different agent-instruction pointers are preserved.

The interface now supports English and Simplified Chinese, with a language switcher and shared controls. Screens adapt to widths down to 360px. Project setup, the top bar, drawer, Needs you and dialogs have been revised.

### Faster first run

The board starts without preparing or downloading agent adapters. At the first stint, Stintwork prefers a compatible installed Claude Code or Codex CLI; otherwise it offers the selected agent's pinned Bundled source. Preparation shows the source, reason and progress, and the verified cache can be reused across projects. The developer still supplies their own login. A cold offline start needs the Stintwork package already cached.

### Stints after a restart

Eligible unfinished Claude Code and Codex stints automatically attempt to continue in the same stint and session after a server restart, using the recorded source and a warm cache. Pending permission requests return to Needs you and become answerable when the agent reconnects. Recovery does not download an agent or repeat the brief.

If recovery fails, Stintwork falls back to an interrupted stint and checkpoint; start a new stint from the recorded state. Legacy logs and experimental Grok Build and Antigravity CLI use this fallback. If Stintwork cannot establish that previous writers have stopped, it blocks mutations and warns instead.

### GitHub Issues as a tracker

Projects configured for GitHub Issues can show qualifying top-level issues as work items and their direct same-repository sub-issues as tickets. The parent body is the spec. Apart from its pull request flow, Stintwork only reads GitHub through `gh`; agents use their own skills and `gh` to write issues. Workflow and gate records remain committed in the worktree, with approvals tied to observed evidence and code. Local Markdown projects remain supported.

GitHub issue data is remote project memory, so it is not available in a bare clone. When access or evidence cannot be verified, Stintwork can show stale or read-only data and refuses actions that require current evidence. For a new Ship pull request, its body includes `Closes #N` for the parent; GitHub closes it when the PR merges into the default branch. An adopted PR keeps its existing body, which the developer should inspect.

### More agents

Antigravity CLI is available as an experimental agent using the installed `agy` executable. Version 1.5.3 is the supported floor; 2.x is incompatible. The developer installs and signs in to it. Antigravity uses its `default` permission mode at every Stintwork permission level, with Stintwork deciding in-worktree approval; safe commands sent as `CommandLine` are recognised. After a server restart it uses the checkpoint fallback; [native restart](../../.scratch/more-agents/issues/07-antigravity-native-restart.md) is deferred.

Grok Build remains experimental. Its 1.0.77 probe passed basic, commands, cancel and resume, but Ask permission was untested under the maintainer's always-approve configuration. Every real stint was rate limited on the maintainer's account; the maintainer accepted that limitation and deferred [end-to-end verification](../../.scratch/agent-polish/issues/04-grok-end-to-end.md).

### Release preparation

The repository includes a [security policy](../../SECURITY.md): once public, report vulnerabilities through GitHub private vulnerability reporting. Only the latest published version receives security fixes. Package metadata includes repository, homepage and bugs links; public access and link checks remain for the release.

The [ACP contract harness](../../spikes/acp-probe/CONTRACT.md) provides a pre-release check across the four agents; `pnpm test:acp-contract` runs its fake-agent self-test. The intended contract policy accepts Grok's always-approve Ask scenario and rate limiting as limitations; a parallel contract change is pending. **Release contract results: pending; record real-agent results for the final revision here.**

## Upgrade

After v0.2.0 is published, stop the running server and run this from the project's main checkout and main branch:

```bash
npx stintwork@0.2.0
```

Node.js 22.12 or newer and Git are required. Use a signed-in agent; GitHub-tracked projects also need `gh` and access to their repository. Stintwork does not handle agent credentials.

## Verification and known limits

- M8's browser suite and maintainer walk-through covered English and Chinese layouts; see the [M8 exit](../../.scratch/ui-foundations/issues/07-m8-exit.md).
- M9's cold packed-tarball runs reached a usable board in 17.4–36.3 seconds on darwin-arm64. Real Claude Code and Codex stints used both Installed and Bundled sources. Offline and interrupted-install coverage was automated only; other platforms were not exercised in that exit. See the [M9 exit](../../.scratch/first-run/issues/09-m9-exit.md).
- M10's real Claude Code and Codex crash-recovery runs reached a handoff and checkpoint on darwin-arm64 with Installed and Bundled sources. Linux recovery has CI coverage; Windows blocks suspension. See the [M10 exit](../../.scratch/stint-resume/issues/09-m10-exit.md).
- M11 shipped after a real GitHub-tracked work item reached a merged PR and the retest follow-ups and cleanup were completed. See the [M11 exit](../../.scratch/github-tracker/issues/08-m11-exit.md).
- Claude Code and Codex are supported. Antigravity CLI is experimental; a real stint finished with a parsed handoff and checkpoint. Grok Build is experimental and has not completed a real stint with a parsed handoff because of rate limiting. See the [M12 exit](../../.scratch/more-agents/issues/06-m12-exit.md).
- Automatic same-session recovery is verified for eligible Claude Code and Codex stints in the M10 exit conditions above. Antigravity native restart is deferred; Antigravity, Grok and legacy logs use checkpoint fallback. The final release-wide ACP contract results are still pending.
- Permission levels depend on the agent's capabilities and are not an independent security boundary. There is no terminal fallback for agents without ACP. The outside-developer test remains after release.
