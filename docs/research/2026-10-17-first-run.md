# Fast first run: installation research (2026-10-17)

## Scope and recommendation

Research for `.scratch/first-run/issues/01-install-research-spike.md`, not an M9 exit result. Inspected checkout `22933703dd29fbf563f53f9d5a935bb66f1bfceb` on darwin-arm64, with Node 22.22.3, npm 10.9.8 and pnpm 11.21.0. No network requests, package fetches, credential reads, login changes, real stints or dependency changes were made. The worktree's `node_modules` and package-level dependency directories link into the main checkout and were treated as read-only.

**Recommendation:** Remove the two ACP adapters from board-time production dependencies and prepare each pinned adapter on explicit first use in a verified, reusable per-user cache, omitting optional native packages and selecting a compatibility-tested installed CLI through its supported override. This changes first-release packaging, not the ACP integration boundary: ADR 0002, ADR 0003, `docs/plan.md` M9 and `.scratch/first-run/spec.md` remain authoritative. No decision record or implementation ticket is filed by this spike.

### Board readiness is part of the installation problem

`packages/server/src/index.ts:129` awaits `refreshAgentRegistry` alongside recovery before the first `/api/*` request completes; `packages/server/src/agent-availability.ts:6` awaits all agent detectors. Codex detection itself launches the adapter; Grok's real ACP detection can consume the entire 60-second board budget. Therefore “install adapters lazily in their resolver” alone would still install Codex before a usable board. Board-time detection must never trigger adapter preparation or await a real-agent session; missing/cold adapters need an explicit not-prepared state or deferred deep check, without conflating this with a missing CLI or required login. Keep authoritative authentication/compatibility checks at explicit preparation or stint start and refresh cached availability afterwards.

## Options and what each actually avoids

| Option | First board | First stint, reuse and limits |
|---|---|---|
| Current normal dependencies | Both adapter graphs and the host-native optional payloads install before startup; minimum measured native payload 237.122 MB compressed here. | No separate adapter setup on first stint; already-installed dependency graph works offline for preparation. Root npx cache eviction/version changes can repeat costs; provider inference still needs its normal connectivity. Current Codex readiness can hold first API responses for its ACP check. |
| Select installed CLIs only, leave dependencies unchanged | **No install-byte reduction.** Claude already selects the installed CLI; setting `CODEX_PATH` only changes the child process. | Avoids executing a duplicate native agent, not downloading it. Requires compatibility checks; old Codex 0.148.0 is not proven. A dedicated install with optional packages omitted can avoid their payloads, but telling every npx user to change global npm settings is not a product solution. |
| First-use pinned adapter cache, default optional packages | Removes both adapter graphs from board installation if detection also stays no-fetch. | Downloads only the chosen adapter graph at first use; unchosen agents cost nothing. Still downloads its native payload even if an override will run a developer CLI. A versioned persistent cache avoids repeating this across projects/root npx revisions. |
| First-use cache **plus compatible installed CLI**, omit optional native packages | Removes both adapter graphs from board installation; proposed choice. | First use downloads adapter JS, SDK and required peers/transitives, not either omitted native executable. Set the verified executable override on every relevant launch path. Preseed/reuse permits offline preparation; a cold offline miss fails cleanly. Actual adapter-only total bytes/time remain unmeasured. |
| Move root adapters to `optionalDependencies` | Default npm still attempts to install them and their graphs: **no guaranteed byte saving**. | Failure can be nonfatal but launch must handle absence. `--omit=optional` skips root adapters entirely; if only native optionals are omitted, adapters need working external overrides. Making something optional is not first-use installation and is not compatibility proof. |

### Conditions on the recommended approach

- **Pin the contract:** keep C **0.88.0** and X **2.1.1** exact, never `latest` or an opportunistic PATH adapter. The new decision record must specify the released transitive lock/integrity mechanism as well: X has ranges, so an exact top-level version alone is not reproducible. Treat S 0.3.293/O 0.159.3 as this spike's resolved reference, not permission to upgrade. Re-run the ACP contract probe whenever the released closure or supported CLI pair changes.
- **Separate trust boundaries:** validate CLI identity/version/interface before use; preserve caller-approved overrides and the existing environment/login ownership. Stintwork must not install an agent CLI, invoke login automatically, inspect credential files or proxy tokens. The currently installed Codex version is an explicit verification gap, not a reason to silently keep a hidden second agent.
- **Keep the mechanism small:** use npm's existing install/integrity checks in a non-project prefix with optional dependencies omitted, a release-controlled dependency closure and user-owned cache, rather than building a package downloader. A cache key needs adapter identity/version, dependency-lock identity, platform/architecture/libc where relevant, and Node compatibility. CLI compatibility must be rechecked when its executable/version changes; do not freeze the developer's login in the cache.
- **No partial cache counts as ready:** prepare in a sibling staging directory, verify the expected manifest, resolved entry and smoke initialization, then atomically publish a completion marker/directory on the same filesystem. Serialize preparation per cache key; handle stale ownership after a killed process. On timeout, cancellation, disk-full, registry or integrity failure, retain any previous good entry, remove only owned incomplete staging, report the cause and provide an explicit retry. Never change a project's manifest or its `node_modules`.
- **Offline:** a missing adapter cache cannot be repaired offline; keep the board usable and explain preparation is needed. A complete adapter cache and compatible installed CLI need no package download to launch, but a real provider-backed stint is not thereby promised to work without network. A fresh offline `npx` also needs the root package in npm's cache; no recommendation makes an uncached root package appear offline.
- **UI and readiness:** show preparation progress/failure and retry where a developer starts a stint, not an unrelated blocking board load. Never allow a background availability refresh or board API to populate the adapter cache. Distinguish installed CLI, prepared adapter, login required, incompatible version and installation error; reuse existing readiness/launch seams rather than adding a general installer framework.

## Proposed budget and cold-install verification

These are **acceptance targets, not achieved measurements**:

- **Board elapsed:** at most **60.0 seconds** from starting npx to a browser-rendered usable board, including root install and normal agent detection. Do not use `STINTWORK_SKIP_AGENT_DETECTION=1` for this measurement.
- **Board network:** at most **10 MiB (10,485,760 bytes)** of registry response bodies, including tarballs and metadata, and at most **10% of a comparable measured current whole-install baseline**. The absolute cap is already only **4.42%** of the two verified native payloads alone; the whole baseline is not yet timed or byte-counted. Log protocol overhead separately if the instrument captures it. Zero native-agent or ACP-adapter tarball requests are allowed before board readiness.
- **Root tarball:** target at most **2 MiB compressed**, included within the 10 MiB board budget. The valid current built root size is still missing; do not use the 11,065-byte incomplete diagnostic as evidence this cap passes.
- **First stint:** measure chosen-adapter-only preparation bytes and time separately, then time through the first real structured stint event. Report cache-cold and cache-warm values; do not move these downloads off the board clock and call the whole first-agent experience measured. A compatible-CLI path must download **zero agent-native payload bytes**. No first-stint timing pass is claimed by this spike.

## Coordinator measurement harness

Run from this checkout with Node >=22.12, npm, Git, OpenSSL (including LibreSSL's
`req -config`), and Playwright Chromium installed. Install the browser outside the
measurement with `pnpm --config.verify-deps-before-run=false --dir packages/web exec playwright install chromium`,
or set `PLAYWRIGHT_CHROME_CHANNEL=chrome` to use installed Chrome. The browser starts
before the clock. Network, local sockets, browser and real agents are coordinator
checks; the offline harness tests do not supply their evidence.

Use new output directories on the same idle host/connection for every invocation.
Replace the conditions text with measured downlink/registry RTT, connection method
and machine load; keep it identical for baseline and candidate. From the repo root:

```sh
measurement_root=$(mktemp -d /tmp/stintwork-first-run-XXXXXX)
conditions='Record actual downlink, registry RTT, connection method and host load here'
node scripts/measure-first-run.mjs --subject stintwork@0.1.1 --runs 3 --out "$measurement_root/baseline" --registry https://registry.npmjs.org --conditions "$conditions"
# Baseline normally exits 1 for candidate budgets; retain its complete results.json.
pnpm --config.verify-deps-before-run=false pack --pack-destination "$measurement_root"
node scripts/measure-first-run.mjs --subject "$measurement_root/stintwork-0.1.1.tgz" --runs 3 --out "$measurement_root/candidate" --registry https://registry.npmjs.org --conditions "$conditions" --baseline "$measurement_root/baseline/results.json"
```

`pnpm pack` runs the normal prepack build; do not replace it with an unbuilt
`--ignore-scripts` pack. Each run retains its fresh consumer, empty-before npm cache,
empty-before agent cache and independent scratch Git project. The board runs with
normal agent detection and `--no-open`. Chromium waits for the sample's button,
opens its detail and waits for the spec text; `usable-board.png` records that state.
Both process-start-to-detail and install-start-to-detail times are recorded.
No real project or global/npm/login configuration is edited. The package's install
scripts, audit and fund traffic are disabled identically for baseline and candidate;
native optional dependencies are **not** omitted. This measures an explicit cold
`npm install` followed by the installed CLI, rather than npx's extra resolver time.

The local forward proxy uses a one-day self-signed certificate, trusted only through
the measured child processes' `NODE_EXTRA_CA_CERTS`. It decrypts registry HTTPS to
count **upstream HTTP response bodies before decompression**, including metadata,
redirects, retries and tarballs, and records every method/URL/status. It separately
counts CONNECT bytes in both directions, **including TLS and HTTP overhead**; these
are not added to body bytes a second time. Request count excludes CONNECT, whose
count is separate. Download accounting covers the selected registry hostname and
`registry.npmjs.org`. Other hosts are forwarded as agent traffic, recorded separately
under `network.agentTraffic` and excluded from download budgets. Their HTTPS tunnels
go directly to the original host without TLS interception or host refusals; only
encrypted tunnel bytes and destinations are visible. The temporary certificate/key are removed on completion;
no system trust or global proxy settings change. HTTPS byte measurement therefore
includes a local TLS interception hop; baseline and candidate use the same transport.

`results.json` retains every run, package SHA-256, version, compressed/unpacked sizes,
file inventory and dependency lock identities. After readiness, an isolated
`npm pack --ignore-scripts` retrieves the already-built installed artifact for
inspection and verifies its SHA-512 against the consumer lock. This inspection is
outside the board clocks and network snapshot. A local input tarball's own SHA-256,
size and hash/inspection time are recorded before install; its public transfer time
is explicitly unmeasured/excluded, and its compressed bytes are added to budget
bytes. This is not a measured full public-download clock. The 2 MiB root target can
be checked against `package.packedBytes`.

Each run exits unsuccessfully for >60 s install-to-usable-detail, >10 MiB budget
bytes, changed agent cache, adapter/native package requests, or incomplete/blocked
registry proxy traffic. With `--baseline`, every candidate must use <=10% of the **smallest**
complete baseline run's budget bytes. Host/Node/npm, registry, conditions and
transport must match. A baseline's candidate-budget failures are allowed for
comparison. Failed baseline attempts stay in the evidence with `status: failed`,
partial `network.responseBodyBytes`, elapsed time and a structured `npmError` summary
alongside the full error. Only completed runs contribute to the reference; both
completed and failed counts are reported. Completed runs may include metered retries.
Comparison is refused when no baseline run completed with valid measurements;
failed attempts do not invalidate a completed repetition. Legacy result files without
status fields are supported. Disk/cache growth and the historical 1078-second
observation cannot substitute for this response-body baseline.

To compare existing measurements without another install, proxy or browser run:

```sh
node scripts/measure-first-run.mjs --compare "$measurement_root/candidate/results.json" --baseline "$measurement_root/baseline/results.json"
```

This mode reads both files without modifying them, recomputes budgets from the saved
measurements, prints PASS/FAIL per candidate run and overall, and exits 1 on failure.
It reports failed baseline counts while excluding their partial transfers from the
reference. Every requested candidate run must complete and meet all budgets;
incomplete or failed candidate runs still fail the overall comparison.
