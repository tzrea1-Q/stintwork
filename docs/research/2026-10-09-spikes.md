## Implications for the production plan

- **ACP is the primary integration path for all three agents.** Keep a terminal fallback, but it can come later.
- **Permission levels need mapping per agent.** Relaybench's own levels must map to each agent's modes. Codex's default mode never asks. Grok has no ACP modes, so its permissions come from flags or config.
- **The app must save git state when a run stops.** Run 1's work was left uncommitted, and run 2's commit mixed in run 1's files while leaving some uncommitted. A WIP checkpoint commit on every stop would keep handoffs clean.
- **Worktrees need git write access and dependencies.** Run 1 couldn't commit because the worktree's git metadata wasn't writable. All runs needed `--config.verify-deps-before-run=false` because the worktree had no fresh dependency install.
- **The brief removes confusion, not exploration.** Agents still read the pointed-to files. That's cheap thanks to caching; this run used about 3.5M input tokens, 96% of them cached.
- **Remaining evidence gaps:**
  - Only 3 runs on one repo.
  - Grok's ask-mode permissions are untested.
  - Run 3 got no "changed since" items.
  - The agents ran headless, so they couldn't ask questions; asking only works over ACP.
